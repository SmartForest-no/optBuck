# nfiBuck

Bucking optimisation prototype for the Norwegian National Forest Inventory
(NFI), developed within the SFI SmartForest project (project 52106).

---

## What is nfiBuck?

`nfiBuck` is an R-based prototype for simulating optimal log cross-cutting
(bucking) on NFI trees. Given taper profiles generated by the `taperNOR`
package and a set of product/price definitions, it finds the bucking pattern
that maximises the total timber value for each tree using dynamic programming.

The prototype covers:

- Reading and stratifying NFI 2020–2024 tree/plot data
- Generating over-bark taper profiles (`taperNOR`)
- Defining product eligibility (sawlog, pulpwood, waste) and candidate log
  geometry using the Huber formula
- Pricing candidate logs against species × length × diameter price matrices
- Selecting the optimal log combination via backward-induction DP
- Summarising results at tree, plot, and stratum level

## What is NOT included

| Item | Reason |
|------|--------|
| `data_raw/` | Raw NFI data are read directly from the Oracle database and are not stored here |
| `data_processed/` | Processed NFI parquet/rds files (~15 MB total); private data — local-only |
| Oracle credentials / `.Renviron` | Never committed — stored outside the repo |
| `outputs/_archive/` | Large archived prototype outputs (redundant after cleanup) |
| `outputs/stem_profiles/` | Derived from private NFI trees; ~1.3 MB binary; regenerate locally |
| `outputs/optimizer_tests/` | Large candidate CSVs (~5.6 MB); regenerate locally |
| `outputs/selected_stratum_summary/` | Large tree-level summary (~4.3 MB); regenerate locally |
| `outputs/mixed_species_example_bucking/` | Prototype run artefacts; regenerate locally |
| `outputs/stratum_tests/` | Binary parquet of private NFI stratum sample |
| `inputs/*.rds` | Binary caches; regeneratable from the CSV source files |

## Running the audits

The audits are self-contained and write their results to `outputs/`. Run
them from the project root (or set `APTER_ROOT`; see "Project root" below).

**Prerequisites**

```r
# CRAN packages
install.packages(c("arrow", "readr", "dplyr"))

# taperNOR — install from source or internal registry
# (required for helpers_taper.R and audit 15)
```

**Audit 14 — validate first helpers**

Checks helpers_paths, helpers_products, helpers_valuation, helpers_audit.
Does not require NFI data.

```r
source("audits/audit_14_validate_first_helpers.R")
# Results: outputs/helper_validation/audit_14_validate_first_helpers.{csv,txt}
```

**Audit 15 — core engine helpers regression**

Checks helpers_taper, helpers_candidate_generation, helpers_dp_optimizer.
Requires `outputs/stem_profiles/stem_profiles_example_500trees.parquet`.
Generate it first by running:

```r
source("scripts/prototype_reference/02_generate_stem_profiles.R")
# (requires data_processed/ NFI files and Oracle access for the upstream script)
```

Then run the audit:

```r
source("audits/audit_15_core_engine_helpers_regression.R")
# Results: outputs/core_engine_helpers_regression/audit_15_core_engine_helpers.{csv,txt}
```

**Audit 16 — sampled-plot backend smoke**

Runs the app backend on `data_processed_github/` and checks that the app's
fast DP optimizer gives the same results as the reference
`optimize_one_tree_dp()`.

```r
source("audits/audit_16_sampled_plot_backend_smoke.R")
# Results: outputs/sampled_plot_backend_smoke/audit_16_sampled_plot_backend_smoke.{csv,txt}
```

**Audit 17 — headless app smoke**

Starts the app in headless Chrome and drives a run, a scenario comparison and
a multiplier scenario. Needs `install.packages(c("shinytest2", "chromote"))`
and Chrome (`chromote::find_chrome()` must return a path; otherwise set
`CHROMOTE_CHROME`). Use `Rscript`, not `source()`, from an interactive session.

```sh
Rscript audits/audit_17_app_smoke.R
# Results: outputs/app_smoke/audit_17_app_smoke.{csv,txt}
```

## Running the app

The Shiny app only needs the sanitized `data_processed_github/` files, which
are already committed to the repo — no Oracle connection or credentials are
required to run it.

**Prerequisites**

```r
install.packages(c("shiny", "arrow", "dplyr", "readr"))

# taperNOR is not on CRAN:
devtools::install_git("https://github.com/SmartForest-no/taperNOR")
```

**Launch**

```r
shiny::runApp("app")   # from the project root (or runApp("app/app.R"))
```

**Project root**

No path is hardcoded. The app, backend and audits resolve the project root
in this order:

1. `APTER_ROOT` environment variable
2. `NFIBUCK_ROOT` environment variable (legacy; still read until the rename)
3. Fallback: the app uses the parent of `app/`; `get_root_dir()`
   (`R/helpers_paths.R`), the backend and the audits walk up from the working
   directory to the first folder containing `R/helpers_paths.R`
   (`get_root_dir()` first checks the options `apter.root` / `nfibuck.root`)

If the resolved folder does not contain `R/helpers_paths.R`, they stop with
an error. To run from elsewhere, set `APTER_ROOT` (e.g. in `~/.Renviron`).
